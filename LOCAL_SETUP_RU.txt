================================================================================
  Раздел A. Что это за проект (кратко)
================================================================================

  • Flutter-клиент (мобильное приложение и/или веб в Chrome).
  • Папка «server» — локальный Node.js backend:
      - авторизация и хранение учебных данных в JSON-файлах (папка server/data/);
      - прокси к OpenRouter для ИИ (чат и генерация плана).
  • Клиент по умолчанию обращается к API:
      - веб-режим:            http://localhost:8787
      - Android-эмулятор:     http://10.0.2.2:8787 (это «localhost компьютера» с точки зрения эмулятора)
  • Папка server/data/ в репозиторий НЕ коммитится (там пользователи и сессии).

  Важно: пока не запущен «server» с корректным OPENROUTER_API_KEY, генерация плана
  может уйти в локальный запасной вариант (в приложении показывается оранжевая плашка).


================================================================================
  Раздел B. Установка Git
================================================================================

  Зачем: клонировать репозиторий, делать коммиты (по желанию).

  1. Сайт: https://git-scm.com/download/win
  2. Скачайте установщик Git for Windows.
  3. Запустите установку. Рекомендуемые опции для начинающих:
       • «Git from the command line and also from 3rd-party software»
       • Остальное можно оставить по умолчанию.
  4. Закройте и снова откройте PowerShell, CMD или терминал в Cursor/VS Code.
  5. Проверка в терминале:

       git --version

     Должна отобразиться версия (например git version 2.x.x).


================================================================================
  Раздел C. Установка Java (JDK) и переменные JAVA_HOME / PATH
================================================================================

  Зачем: сборка Android-проекта Gradle использует JDK. Android Studio часто
  ставит свою встроенную JBR (JetBrains Runtime) — этого иногда достаточно.

  Вариант 1 — отдельная установка JDK 17 (LTS), удобно для явного JAVA_HOME
  ---------------------------------------------------------------------------
  1. Откройте https://adoptium.net/ (Eclipse Temurin) или другой дистрибутив JDK 17.
  2. Скачайте Windows x64 installer для JDK 17.
  3. Установите, запомните путь. Пример:
       C:\Program Files\Eclipse Adoptium\jdk-17.0.12.7-hotspot\
  4. Внутри этой папки должны быть подпапки bin, lib, и т.д.

  Вариант 2 — использовать JDK из Android Studio
  -----------------------------------------------
  После установки Android Studio путь часто такой:
    C:\Program Files\Android\Android Studio\jbr
  (точный путь можно посмотреть в настройках Studio: путь к встроенному JDK).

  Настройка переменных среды Windows (JAVA_HOME и PATH)
  -----------------------------------------------------
  1. Нажмите Win + R, введите:  sysdm.cpl  Enter.
  2. Вкладка «Дополнительно» → кнопка «Переменные среды…».
  3. Блок «Системные переменные» (или «Переменные среды пользователя»):

       а) Создайте переменную (если её ещё нет):
            Name:   JAVA_HOME
            Value:  папка JDK без bin на конце
              Пример: C:\Program Files\Eclipse Adoptium\jdk-17.0.12.7-hotspot

       б) Найдите переменную Path → «Изменить» → «Создать» → добавьте строку:

            %JAVA_HOME%\bin

  4. Нажмите OK везде.
  5. Закройте все окна терминала и откройте новое.
  6. Проверка:

       java -version

     Ожидается версия 17.x (или та, что вы ставили).

       where java

     Должен указывать на JDK из JAVA_HOME\bin, а не случайную копию.


================================================================================
  Раздел D. Установка Flutter SDK и переменная PATH
================================================================================

  1. Официальная документация: https://docs.flutter.dev/get-started/install/windows
  2. Скачайте архив Flutter SDK для Windows (stable).
  3. Распакуйте в КОРОТКИЙ путь БЕЗ пробелов и кириллицы, например:

       C:\src\flutter

     Не рекомендуется: длинные пути в OneDrive, папки с кириллицей в пути.

  4. Добавьте в PATH путь к папке bin:

       C:\src\flutter\bin

     Как добавить PATH: Win + R → sysdm.cpl → Переменные среды → Path → Изменить
     → Создать → вставить полный путь ...\flutter\bin → OK.

  5. Новый терминал. Проверка:

       flutter --version

  6. Диагностика:

       flutter doctor

     Прочитайте вывод: для Android обычно нужны Android toolchain, плагины Studio
     и принятие лицензий (см. раздел E и K).

  7. Политика выполнения скриптов PowerShell (если flutter.bat ругается):
     Только для текущего пользователя, осознанно:

       Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

     Подтвердите Y при запросе.


================================================================================
  Раздел E. Android Studio, Android SDK, эмулятор, ANDROID_HOME
================================================================================

  Установка Android Studio
  ------------------------
  1. Сайт: https://developer.android.com/studio
  2. Установите Android Studio (можно оставить типовой набор компонентов).
  3. При первом запуске дойдите до экрана приветствия / обновлений SDK.

  Android SDK
  -----------
  1. Android Studio → «More Actions» → SDK Manager (или File → Settings → SDK).
  2. Вкладка SDK Platforms:
       • Отметьте хотя бы одну свежую версию API (например Android 14 / API 34
         или новее в зависимости от списка в Studio).
  3. Вкладка SDK Tools:
       • Android SDK Build-Tools
       • Android SDK Platform-Tools
       • Android Emulator
       • (опционально) Google Play services / образы с Google APIs
  4. Apply / OK — дождитесь загрузки.

  Путь к SDK (важно для ANDROID_HOME)
  ------------------------------------
  В SDK Manager сверху указан «Android SDK Location», часто:

       C:\Users\<ВАШ_ЛОГИН>\AppData\Local\Android\Sdk

  Скопируйте этот путь.

  Переменные ANDROID_HOME (или ANDROID_SDK_ROOT) и PATH
  -----------------------------------------------------
  1. sysdm.cpl → Переменные среды.
  2. Создайте системную (или пользовательскую) переменную:

       Имя: ANDROID_HOME
       Значение: например C:\Users\<Вы>\AppData\Local\Android\Sdk

     (Некоторые инструменты ожидают ещё ANDROID_SDK_ROOT тем же значением —
      при желании создайте дубликат с тем же путём.)

  3. В переменную Path добавьте:

       %ANDROID_HOME%\platform-tools
       %ANDROID_HOME%\emulator

     (Папка emulator появляется после установки эмулятора из SDK Tools.)

  4. Новый терминал. Проверка:

       adb version

  Лицензии Android SDK
  --------------------
  В терминале:

       flutter doctor --android-licenses

  На вопросы отвечайте y (yes), пока не завершится.

  Создание виртуального устройства (AVD)
  --------------------------------------
  1. Android Studio → Device Manager (иконка телефона).
  2. Create Device → выберите телефон (например Pixel 6).
  3. Выберите образ системы (Download, если нужно) — лучше x86_64 или arm64
     в зависимости от вашего ПК.
  4. Завершите мастер, запустите эмулятор кнопкой ▶.

  Проверка с Flutter
  ------------------
       flutter devices

  Должен появиться эмулятор (emulator-5554 и т.п.).

  Раздел F. Node.js для backend

================================================================================
  Раздел G. Получение кода и структура папок
================================================================================

  Клонирование (если проекта ещё нет на диске)
  ---------------------------------------------
  Выберите родительскую папку, например Desktop:

       cd %USERPROFILE%\Desktop
       git clone https://github.com/baaukanr/studymate_ai.git
       cd studymate_ai

  Структура (важное)
  ------------------
    studymate_ai\
      lib\                 — код Flutter
      server\              — Node backend (index.js, package.json)
      server\data\         — создаётся при работе; НЕ в git (учётные данные)
      pubspec.yaml         — зависимости Flutter
      android\, ios\, web\ — платформенные проекты Flutter

  Ключ API OpenRouter
  -------------------
  Зарегистрируйтесь на https://openrouter.ai, создайте API key.
  Ключ НЕ вставляйте в публичный репозиторий; храните локально или в переменных среды.


================================================================================
  Раздел H. Запуск сервера (proxy, auth, OpenRouter)
================================================================================

  Откройте терминал.

  1. Перейдите в папку server (путь подставьте свой):

       cd C:\Users\...\Desktop\studymate_ai\server

  2. Установите зависимости (один раз или после обновления package.json):

       npm install

  3. Перед КАЖДЫМ запуском в этой же сессии PowerShell задайте ключ и модель
     (пример для PowerShell):

       $env:OPENROUTER_API_KEY = "sk-or-v1-ВАШ_КЛЮЧ_СЮДА"
       $env:OPENROUTER_MODEL   = "openai/gpt-4o-mini"

     Для CMD (одноразово в окне cmd):

       set OPENROUTER_API_KEY=sk-or-v1-ВАШ_КЛЮЧ
       set OPENROUTER_MODEL=openai/gpt-4o-mini

  4. Запуск:

       npm start

  5. Окно с сервером не закрывайте, пока тестируете приложение.
     По умолчанию сервер слушает порт 8787 (см. вывод в консоли или server/index.js).

  Постоянные переменные среды Windows (опционально)
  -------------------------------------------------
  sysdm.cpl → Переменные среды → создать пользовательские:
    OPENROUTER_API_KEY = ваш_ключ
    OPENROUTER_MODEL   = openai/gpt-4o-mini
  После этого новые терминалы будут видеть ключ без ручного set.

  Проверка, что сервер жив (опционально)
  --------------------------------------
  Браузер или curl:

       http://localhost:8787/health

  Ожидается JSON с ok: true (если такой маршрут включён в вашей версии server).


================================================================================
  Раздел I. Запуск Flutter-приложения (веб и Android)
================================================================================

  Откройте ВТОРОЙ терминал (сервер в первом должен продолжать работать).

  1. Перейдите в корень проекта Flutter:

       cd C:\Users\...\Desktop\studymate_ai

  2. Подтяните зависимости:

       flutter pub get

  3. Проверка устройств:

       flutter devices

  Запуск в браузере Chrome (удобно как «локальный сайт»)
  -------------------------------------------------------
       flutter run -d chrome

  После сборки откроется окно браузера. URL обычно localhost с портом,
  который выберет Flutter (не путать с портом 8787 backend).

  Важно: для веба клиент по умолчанию ходит на http://localhost:8787 —
  сервер из раздела H должен быть запущен на том же компьютере.

  Запуск на эмуляторе Android
  ---------------------------
  1. Запустите AVD в Android Studio (эмулятор должен быть «загружен» до домашнего экрана).
  2. В терминале:

       flutter run

     Если устройств несколько, укажите идентификатор из flutter devices, например:

       flutter run -d emulator-5554

  Для эмулятора в коде уже используется http://10.0.2.2:8787 к вашему ПК
  (см. lib/config/api_base.dart) — это нормально для стандартного Android Emulator.

  Физический телефон по USB / Wi‑Fi
  --------------------------------
  • Включите режим разработчика и отладку по USB на телефоне.
  • Подключите USB, примите отпечаток RSA на телефоне.
  • adb devices — должен показать device.
  • flutter run

  Примечание: телефон НЕ видит localhost вашего ПК как 127.0.0.1.
  Нужен IP компьютера в локальной сети, например 192.168.0.10, и тогда база URL
  должна быть http://192.168.0.10:8787. Это настраивается через изменение
  resolveApiBaseUrl / dart-define (см. раздел L).


================================================================================
  Раздел J. Типичный порядок действий каждый день
================================================================================

  1. Запустить Android-эмулятор (если нужен Android), дождаться загрузки.
  2. Терминал 1:
       cd ...\studymate_ai\server
       (при необходимости задать OPENROUTER_API_KEY)
       npm start
  3. Терминал 2:
       cd ...\studymate_ai
       flutter pub get        (после git pull имеет смысл)
       flutter run -d chrome  ИЛИ  flutter run -d emulator-...
  4. Регистрация / вход в приложении — через ваш локальный backend.
  5. Данные пользователей и планов для разработки лежат в server\data\ локально.


================================================================================
  Раздел K. Решение частых проблем
================================================================================

  K1. "flutter не является внутренней или внешней командой"
      → Не добавлен путь ...\flutter\bin в PATH, либо не открыт новый терминал.

  K2. flutter doctor: Android licenses not accepted
      → flutter doctor --android-licenses

  K3. Gradle / Java ошибки при сборке Android
      → Проверить JAVA_HOME (JDK 17), совместимость версии Gradle в проекте.

  K4. Оранжевая плашка в плане «ИИ не сгенерирован» / сервер не ответил
      → Не запущен npm start; неверный адрес API; нет сети; неверный ключ;
         файрвол Windows заблокировал node.exe — разрешить в брандмауэре для частных сетей.

  K5. Веб открывается, но запросы к API не идут
      → Убедитесь, что server слушает 8787; в браузере проверьте localhost:8787/health
         (или соответствующий маршрут). Проверьте консоль сервера на ошибки.

  K6. Эмулятор не видит backend на localhost:8787
      → Для эмулятора используйте логику 10.0.2.2:8787 (уже в api_base для Android).
         Если вы меняли код базового URL — проверьте его снова.

  K7. Очень старая версия Flutter (например 2.2.x)
      → Скачайте актуальный stable Flutter с сайта; старые SDK дают странные ошибки
         на веб и с пакетами.

  K8. Кириллица или пробелы в пути к проекту
      → Иногда ломают инструменты. По возможности держите проект в коротком пути
         вроде C:\dev\studymate_ai.


================================================================================
  Раздел L. Дополнительно: dart-define и смена базового URL API
================================================================================

  В lib/config/api_base.dart база задаётся через resolveApiBaseUrl().
  Можно переопределить без правки файла, если в проекте поддержано:

       --dart-define=AUTH_API_BASE_URL=http://192.168.1.100:8787

  Точное имя ключа смотрите в исходнике resolveApiBaseUrl (String.fromEnvironment).

  Пример запуска с подстановкой IP вашего ПК в локальной сети (для реального телефона):

       flutter run --dart-define=AUTH_API_BASE_URL=http://192.168.1.100:8787

  Убедитесь, что ПК и телефон в одной Wi‑Fi сети и брандмауэр разрешает входящие
  подключения к Node на порту 8787 (или временно отключите только для теста —
  безопаснее добавить правило только для частных сетей).
